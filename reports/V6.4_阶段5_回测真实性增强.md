## 一、模块架构说明

### 1.1 设计原则

- **新增独立模块**：`RealisticBacktestEngine` 类，不修改现有 `backtest_engine.py`、`backtest.py`、`event_backtest_engine.py`
- **可开关**：`enable_realistic=True/False`，关闭时使用原始逻辑（T日收盘价成交、无费用），完全向后兼容
- **真实数据**：读取通达信本地K线数据，不使用模拟数据

### 1.2 核心类结构

```
RealisticBacktestEngine
├── __init__(enable_realistic, commission_rate, min_commission, stamp_tax, slippage, max_volume_ratio, initial_capital)
├── run_backtest(signals, kline_data) → BacktestResult
├── _check_future_function(signal_date, trade_date) → bool
├── _calculate_buy_price(open_price) → float
├── _calculate_sell_price(open_price) → float
├── _calculate_commission(amount) → float
├── _calculate_stamp_tax(amount) → float
├── _check_trade_limit(...) → (bool, str)
├── _calculate_metrics(...) → BacktestMetrics
└── generate_ma_crossover_signals(kline_data, short_period, long_period) → List[Dict]  [静态方法]
```

### 1.3 数据类

| 类 | 用途 |
|----|------|
| `TradeRecord` | 单笔交易记录（信号日/成交日/成交价/费用/盈亏） |
| `BacktestMetrics` | 回测指标（收益/回撤/胜率/费用/检测统计） |
| `BacktestResult` | 完整回测结果（指标+交易记录+权益曲线+配置） |

## 二、真实性增强项说明

### 2.1 防未来函数检测

**规则**：信号产生日期（T日）必须 < 成交日期（T+1日）。

- 检测方法：`_check_future_function(signal_date, trade_date)`
- 所有信号在T日收盘后产生，T+1日开盘成交
- 检测到未来函数时记录并通过T+1机制自动修正
- 输出统计：`future_function_detected`、`future_function_fixed`

### 2.2 T+1成交机制

| 操作 | 信号产生 | 成交时间 | 成交价格 |
|------|----------|----------|----------|
| 买入 | T日收盘 | T+1日开盘 | 开盘价×(1+滑点) |
| 卖出 | T日收盘 | T+1日开盘 | 开盘价×(1-滑点) |

- 持仓期间不能当天买入当天卖出（A股T+1规则）
- 如T+1日开盘涨停/跌停/停牌，自动顺延至下一可交易日

### 2.3 滑点设置

- 默认滑点：**0.1%**（可配置）
- 买入成交价 = 开盘价 × (1 + 0.001)
- 卖出成交价 = 开盘价 × (1 - 0.001)
- 滑点成本单独统计：`slippage_cost`

### 2.4 手续费

- 默认佣金率：**万2.5**（0.025%）
- 最低佣金：**5元**（不足5元按5元收）
- 买入和卖出都收取
- 公式：`max(成交金额 × 0.00025, 5.0)`

### 2.5 印花税

- 税率：**千1**（0.1%）
- **仅卖出时收取**（A股规则）
- 公式：`成交金额 × 0.001`

### 2.6 成交限制

| 限制项 | 规则 | 处理方式 |
|--------|------|----------|
| 成交量 | 单笔 ≤ 当日成交量×10% | 超过则减少股数或跳过 |
| 涨停 | T+1开盘涨停时无法买入 | 顺延至下一交易日 |
| 跌停 | T+1开盘跌停时无法卖出 | 顺延至下一交易日 |
| 停牌 | 开盘价=0或成交量=0 | 顺延至复牌 |

## 三、回测指标计算公式

| 指标 | 公式 |
|------|------|
| 总收益率 | (最终资金 - 初始资金) / 初始资金 × 100% |
| 年化收益率 | (1 + 总收益率)^(252/交易日数) - 1 |
| 最大回撤 | max((峰值 - 谷值) / 峰值 × 100%) |
| 胜率 | 盈利交易数 / 总交易数 × 100% |
| 盈亏比 | 平均盈利 / 平均亏损绝对值 |
| 夏普比率 | (日均收益率 / 日收益率标准差) × √252 |
| 平均持仓天数 | Σ持仓天数 / 交易次数 |
| 总交易成本 | 手续费 + 印花税 + 滑点成本 |

## 五、防未来函数检测验证

### 5.1 T+1成交验证

```
买入交易总数: 5
T+1成交（信号日<成交日）: 5
同日成交（信号日=成交日）: 0
因涨跌停/停牌顺延: 1
✓ 所有买入均为T+1成交，无未来函数
```

### 5.2 检测统计

| 检测项 | 次数 |
|--------|------|
| 检测到未来函数 | 0 |
| 已修正次数 | 0 |
| 涨停无法买入 | 1 |
| 跌停无法卖出 | 0 |
| 成交量限制跳过 | 0 |

**结论**：所有信号均为T日产生、T+1成交，未检测到未来函数。1次涨停顺延正常工作。

## 六、集成方式说明

### 6.1 基本使用

```python
from strategy.realistic_backtest_engine import RealisticBacktestEngine

# 真实性增强模式（默认）
engine = RealisticBacktestEngine(enable_realistic=True)
result = engine.run_backtest(signals, kline_data)

# 原始模式（向后兼容）
engine_naive = RealisticBacktestEngine(enable_realistic=False)
result_naive = engine_naive.run_backtest(signals, kline_data)
```

### 6.2 自定义参数

```python
engine = RealisticBacktestEngine(
    enable_realistic=True,
    commission_rate=0.0003,   # 万3
    min_commission=5.0,
    stamp_tax=0.001,          # 千1
    slippage=0.002,           # 0.2%滑点
    max_volume_ratio=0.05,    # 5%成交量限制
    initial_capital=500000,   # 50万
)
```

### 6.3 信号格式

```python
signals = [
    {"date": "20260101", "type": "buy", "price": 10.50, "reason": "MA金叉"},
    {"date": "20260115", "type": "sell", "price": 12.30, "reason": "MA死叉"},
]
```

### 6.4 与现有回测模块的关系

| 现有模块 | 状态 | 集成方式 |
|----------|------|----------|
| `strategy/backtest_engine.py` | 保留不变 | 可在外部调用 `RealisticBacktestEngine` 做对比 |
| `strategy/backtest.py` | 保留不变 | 其T日收盘价成交逻辑存在未来函数，建议用新引擎替代 |
| `strategy/event_backtest_engine.py` | 保留不变 | 事件回测可接入新引擎做真实性校验 |
| `strategy/return_calculator.py` | 保留不变 | 收益计算独立，不受影响 |

## 七、后续优化方向

1. **多股票组合回测**：当前为单股票回测，后续可扩展为多股票资金分配组合回测
2. **动态滑点**：根据成交量和波动率动态调整滑点，小盘股滑点更大
3. **涨跌停精确判断**：当前用前收盘×1.1判断，需考虑ST股5%涨跌停、科创板20%等
4. **分红除权处理**：回测期间遇到分红除权时，价格需复权处理
5. **集成到UI**：在回测中心页面增加"真实性增强"开关，实时对比两种模式
6. **批量回测**：支持对股票池批量运行真实性回测，输出策略真实胜率排名
7. **滑点模型优化**：引入买卖盘口深度模型，更精确模拟大单冲击成本
