## 三、根本原因定位

### 🔴 瓶颈1（最主要）：NewsService._load_stock_names() 过度获取全市场财务信息

**文件**: `service/unified_data_service.py` 第40-55行

**问题代码**:
```python
def _load_stock_names(self):
    """加载股票名称映射用于新闻股票识别"""
    from utils.tdx_stock_list import get_full_market_quotes
    stocks = get_full_market_quotes(main_board_only=False, exclude_st=False)
    # 只需要 name→code 映射，但获取了全市场行情+财务信息！
```

**调用链**:
```
NewsService.__init__()
  → _load_stock_names()
    → get_full_market_quotes(main_board_only=False, exclude_st=False)
      → get_realtime_quotes_tdx(5217 codes)  # 分批，约105批
      → enrich_finance_info()
        → get_finance_info_batch(5217 codes)  # 🔴 逐只请求！
```

**get_finance_info_batch 实现** (`utils/tdx_stock_list.py` 第183-233行):
```python
for code in need_fetch:  # 5217次循环！
    data = api.get_finance_info(market, code)  # 每次一只股票！
```

**耗时估算**:
- 5217只股票 × 每次财务信息请求约30-50ms = **156-260秒（2.5-4.3分钟）**
- 加上实时行情分批请求约10-30秒
- **总计约3-5分钟**，与用户反馈的"约5分钟"完全吻合！

**问题本质**: NewsService只需要 `name→code` 映射用于新闻股票识别，但 `get_full_market_quotes()` 会获取全市场5217只股票的**实时行情+财务信息（市值/换手率/行业）**，完全是过度设计。股票名称映射只需要 `get_stock_list_tdx()`（只返回code/name，不获取行情和财务）。

## 十七、优化方案（只提方案，不执行）

### 方案A: 修复NewsService._load_stock_names()过度获取问题（预计节省3-5分钟）

**问题**: 只需要name→code映射，却获取了全市场行情+财务信息

**优化**:
```python
# 原代码（慢）
def _load_stock_names(self):
    stocks = get_full_market_quotes(main_board_only=False, exclude_st=False)  # 3-5分钟！
    for s in stocks:
        self._stock_name_map[s['name']] = s['code']

# 优化后（快）
def _load_stock_names(self):
    from utils.tdx_stock_list import get_stock_list_tdx
    stocks = get_stock_list_tdx()  # 只返回code/name，<1秒！
    for s in stocks:
        self._stock_name_map[s['name']] = s['code']
```

**预计效果**: 启动时间从3-5分钟降至<10秒

### 方案B: NewsPage新闻加载改为异步/延迟加载（预计节省5-40秒）

**问题**: NewsPage.__init__同步调用_load_news()阻塞主线程

**优化**:
1. NewsPage.__init__只创建UI，不加载新闻
2. 使用QTimer.singleShot(100, self._load_news)延迟加载，让主窗口先显示
3. 或者使用QThread后台加载新闻，加载完成后更新UI

**预计效果**: 主窗口显示时间从>90秒降至<2秒

### 方案C: 非首屏页面懒加载（预计节省0.7秒）

**问题**: StockDetailPage在启动时就创建KlineContainer/ECharts

**优化**:
1. Tab页面首次点击时才创建对应页面
2. 或者StockDetailPage首次显示时才初始化KlineContainer

**预计效果**: 启动时间再减少0.5-1秒

### 方案D: 统一行情缓存，避免重复请求

**问题**: 不同模块可能重复请求同一只股票的行情/财务信息

**优化**:
1. 建立UnifiedMarketDataCenter统一缓存
2. 同一只股票同一时间只请求一次
3. 缓存过期自动刷新

### 方案E: get_finance_info_batch批量请求优化

**问题**: 当前逐只股票请求财务信息

**优化**:
1. 研究通达信API是否支持批量获取财务信息
2. 如果不支持，使用线程池并发请求（但要注意通达信连接数限制）
3. 或者使用其他数据源（如东方财富批量接口）

## 二十、最终结论

### 为什么程序启动需要约5分钟？

**根本原因**: `NewsService.__init__` 中的 `_load_stock_names()` 方法调用了 `get_full_market_quotes(main_board_only=False, exclude_st=False)`，该函数会获取全市场**5217只股票**的实时行情和财务信息。其中 `get_finance_info_batch()` 是**逐只股票请求**财务信息，5217只股票 = 5217次网络请求，每次30-50ms，总计约**3-5分钟**。

而NewsService只需要 `name→code` 映射用于新闻股票识别，完全不需要行情和财务信息。这是典型的**过度获取**问题。

### 次要原因

1. `NewsPage._load_news()` 在页面初始化时**同步**调用4个新闻接口网络请求，阻塞主线程5-40秒
2. 所有Tab页面启动时一次性创建，个股分析页面的KlineContainer/ECharts也在启动时初始化

### 责任归属

| 瓶颈 | 类型 | 文件 | 函数 |
|------|------|------|------|
| 5217次逐只财务请求 | 🔴 主线程阻塞 | `utils/tdx_stock_list.py` | `get_finance_info_batch()` |
| 过度获取全市场数据 | 🔴 设计问题 | `service/unified_data_service.py` | `NewsService._load_stock_names()` |
| 同步新闻加载 | 🟡 主线程阻塞 | `ui/battle_console_v2.py` | `NewsPage.__init__` |

### 最直接的优化

将 `NewsService._load_stock_names()` 中的 `get_full_market_quotes()` 替换为 `get_stock_list_tdx()`（只返回code/name，不获取行情和财务），预计启动时间从3-5分钟降至<10秒。
