## 二、缓存系统架构

### 2.1 ScanCacheManager 核心功能

```
ScanCacheManager
├── 扫描结果缓存（scan_result_cache.json + cache_info.json）
│   ├── 保存：扫描完成后自动保存完整结果
│   ├── 加载：版本匹配+有效期内直接返回StockScanResult列表
│   ├── 版本检查：CACHE_VERSION不匹配立即失效
│   └── 有效期：盘中30分钟 / 非交易时段当天有效 / 开盘前失效
├── 行情缓存（quote_cache/目录，按代码分文件）
│   └── 有效期30分钟
├── 评分缓存（score_cache/目录，按代码+日期分文件）
│   └── 当天有效，次日自动清理过期文件
└── 缓存信息查询
    ├── get_cache_info()：最后扫描时间/股票数量/状态/版本
    ├── is_cache_valid()：缓存是否有效
    └── clear_cache()：清除扫描缓存
```

### 2.2 缓存有效期规则

| 缓存类型 | 有效期 | 说明 |
|----------|--------|------|
| 扫描结果 | 30分钟 | 盘中（09:30-11:30/13:00-15:00） |
| 扫描结果 | 当天 | 非交易时段（收盘后保存最终股票池） |
| 扫描结果 | 立即失效 | 开盘前（09:00-09:30）提示重新扫描 |
| 行情数据 | 30分钟 | 单只股票行情 |
| 评分数据 | 当天 | 当天有效，次日清除 |
| 版本不匹配 | 立即失效 | CACHE_VERSION变更后重新扫描 |

### 2.3 缓存文件结构

```
data/cache/
├── cache_info.json              # 缓存元信息
├── scan_result_cache.json       # 完整扫描结果（StockScanResult序列化）
├── quote_cache/                 # 行情缓存（按代码分文件）
│   ├── 600000.json
│   └── 000001.json
└── score_cache/                 # 评分缓存（按代码+日期分文件）
    ├── 600000_20260820.json
    └── 000001_20260820.json
```

## 三、UI改动

### 3.1 工具栏3个按钮

| 按钮 | 功能 |
|------|------|
| ⚡ **快速加载缓存** | 从缓存加载股票池（1-3秒），缓存过期也加载但提示重新扫描 |
| 🔄 **重新全市场扫描** | 清除旧缓存并重新执行三层扫描（原扫描逻辑） |
| 🔃 **刷新行情** | 只刷新当前股票池行情（批量获取最新价/涨跌幅），不重新跑模型 |

### 3.2 缓存状态条

工具栏下方显示：
```
💾 最后扫描: 2026-08-20 13:40:00 | 缓存股票: 86只 | 模式: 快速扫描 | 交易时段 | 状态: 缓存有效(25分钟后过期)
```
- 绿色：缓存有效
- 橙色：已过期/开盘前失效
- 灰色：无缓存

### 3.3 启动行为

- 面板打开后300ms延迟检查缓存（不阻塞UI初始化）
- 缓存有效 → 自动加载，1-3秒显示股票池
- 缓存无效 → 显示"请点击重新全市场扫描开始"，不自动扫描

### 3.4 刷新行情功能

- 获取当前股票池所有代码
- 优先批量获取实时行情（get_realtime_quotes）
- 批量失败则逐只获取K线最新价
- 更新价格/涨跌幅，不重新跑模型和评分
- 几十只股票几秒完成

## 四、缓存流程说明

### 4.1 首次扫描流程
```
程序启动 → 面板打开 → 检查缓存（无缓存）→ 提示"请扫描"
用户点击"重新全市场扫描" → 三层扫描（L1→L2→L3）→ 自动保存缓存 → 显示股票池
```

### 4.2 二次启动流程（30分钟内）
```
程序启动 → 面板打开 → 检查缓存（有效）→ 自动加载缓存（0.003秒）→ 显示股票池
```

### 4.3 盘中刷新流程
```
股票池已显示 → 点击"刷新行情" → 批量获取最新行情 → 更新价格/涨跌幅 → 刷新表格
```

## 七、技术细节

1. **numpy类型兼容**：自定义`_CacheJSONEncoder`处理`np.bool_`/`np.integer`/`np.floating`/`np.ndarray`序列化
2. **StockScanResult完整反序列化**：缓存加载时重建ModelMatch/AIScore/BuySellSignal/KlineAnnotation等嵌套dataclass
3. **线程安全**：缓存文件读写在扫描线程中完成，不阻塞UI
4. **kline_data不缓存**：K线数据量大，缓存时自动排除，详情页按需加载
5. **过期评分缓存自动清理**：初始化时清理非当天的评分缓存文件
6. **全局单例**：`get_scan_cache_manager()`确保全局唯一缓存管理器实例
