## 二、方案1：本地K线持久化缓存（DuckDB）

### 2.1 架构

```
KlineCacheDB (DuckDB)
├── 表结构: kline_cache(code, date, open, high, low, close, volume, amount, update_time)
├── 主键: (code, date) — UPSERT支持
├── 索引: code, date
└── 方法:
    ├── get_kline(code, days) — 从本地缓存读取
    ├── save_kline(code, kline_data) — 批量写入/更新
    ├── get_last_date(code) — 返回缓存最新日期
    ├── get_cached_codes() — 返回所有已缓存代码
    ├── clean_expired(days=30) — 清理过期缓存
    └── cache_stats() — 返回缓存统计
```

### 2.2 增量更新策略

在 `_get_kline_with_fallback()` 中：
1. **缓存最新日期 == 今天** → 直接返回缓存的120日K线（秒级）
2. **缓存最新日期 == 昨天** → 只请求今天1天增量，合并后返回
3. **缓存不足或过期** → 请求完整120日，保存到缓存

### 2.3 缓存文件

- 路径：`data/cache/kline_cache.duckdb`
- 首次扫描后控制台打印：`[KLINE CACHE] 已缓存 XXX 只股票，共 XXX 根K线`
- 扫描完成后自动清理超过30天未更新的缓存

## 三、方案3：腾讯批量行情

### 3.1 架构

```
data/tencent_quote.py
├── get_batch_quotes(codes) — 批量获取行情（每批50只，超时10秒，重试2次）
├── get_single_quote(code) — 获取单只行情
├── get_cached_batch_quotes(codes) — 带30分钟缓存的批量行情
├── _parse_tencent_response(text) — 解析腾讯接口返回
└── _convert_code_to_tencent(code) — 代码转换（6开头→sh，其他→sz）
```

### 3.2 接口细节

- 接口：`https://qt.gtimg.cn/q=sz000678,sh600000,...`
- 每批最多50只股票（腾讯接口限制）
- 返回字段：名称/代码/最新价/昨收/今开/涨跌额/涨跌幅/最高/最低/成交量/成交额/换手率/流通市值/总市值
- 超时10秒，重试2次，失败返回空dict不阻塞

### 3.3 刷新行情优化

`ForceBehaviorStrategy.refresh_quotes()` 优先使用腾讯批量行情：
1. 腾讯批量成功 → 直接更新价格/涨跌幅（1-2秒完成几十只）
2. 腾讯批量失败 → 降级到现有接口批量行情
3. 都失败 → 逐只获取K线最新价

## 四、方案4：启动预加载

### 4.1 架构

```
main_window.py
└── __init__末尾: QTimer.singleShot(3000, self._preload_force_behavior)
    └── _preload_force_behavior()
        ├── 检查交易时段（非交易时段跳过）
        ├── 检查已有有效缓存（有则跳过）
        └── 启动后台daemon线程执行 strategy.quick_scan()
            ├── 设置数据提供者
            ├── 执行快速扫描（30日预筛+120日深度）
            ├── 结果自动保存到V1.2.3扫描结果缓存
            └── 控制台打印: [PRELOAD] 预加载完成，XX只候选股
```

### 4.2 面板打开时的行为

`force_behavior_panel.py` 的 `_auto_load_cache()`：
1. 检查预加载状态 `strategy.is_preloading()`
   - 正在预加载 → 显示"正在后台预加载...请稍候"，启动QTimer每2秒检查
   - 预加载完成 → 自动加载结果
2. 检查V1.2.3扫描结果缓存
   - 有效 → 自动加载（1-3秒）
   - 无效 → 显示"请点击重新全市场扫描开始"

### 4.3 预加载策略

- **只在交易时段启动**（9:30-11:30, 13:00-15:00）
- 非交易时段不预加载（节省资源）
- 使用快速扫描模式（30日预筛+120日深度）
- 预加载结果和手动扫描结果共用同一缓存
- 后台daemon线程，不阻塞UI，不显示进度条
