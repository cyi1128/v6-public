## 一、四层扫描架构说明

### 1.1 设计目标

解决当前扫描数量限制问题（固定500只、AI只分析100只），改为四层逐级过滤扫描，在提高扫描速度的同时避免漏股。

### 1.2 架构层次

```
L1 全市场基础过滤（2232 → 1750）
    沪深主板 / 非ST / 股价≥5 / 非停牌
    ↓
L2 技术过滤（1750 → 1456）
    MA趋势 / 成交量 / KDJ / MACD / 涨停历史（满足≥2项）
    ↓
L3 多因子评分（1456 → 300）
    技术面(40%) + 资金面(30%) + 趋势面(30%)，保留Top 300
    ↓
L4 AI深度分析（300 → Top 80）
    三模型分析 + AI综合评分，输出最终候选80只
```

### 1.3 核心类

| 类名 | 说明 |
|------|------|
| `LayeredScanner` | 四层扫描器主类，封装L1-L4全部逻辑 |
| `LayerStats` | 单层扫描统计（输入/通过/过滤/耗时/原因分布） |
| `LayeredScanResult` | 单只股票扫描结果（技术指标+因子评分+模型评分+综合评分） |

### 1.4 设计原则

- **独立模块**：新增代码不修改现有策略核心逻辑
- **逐级收敛**：每层输入数量递减，计算量逐层降低
- **并行加速**：L2/L3/L4均使用8线程并行计算
- **深度分析聚焦**：L4只对Top 80只做三模型+综合评分，避免全市场AI分析
- **真实数据**：全部使用通达信本地K线数据，无模拟数据

## 二、每层过滤条件和阈值

### 2.1 L1 全市场基础过滤

| 过滤项 | 阈值 | 说明 |
|--------|------|------|
| 市场板块 | 沪深主板 | 60开头（沪市）、000/001开头（深市） |
| ST状态 | 非ST/*ST | 股票名称包含"ST"即排除 |
| 最低股价 | ≥ 5.0元 | 排除低价股和仙股 |
| 停牌状态 | 成交量 > 0 | 从最新K线判断非停牌 |
| 数据有效性 | 有最新K线 | 排除退市/无数据股票 |

**数据源**：`tdx_data_engine.get_all_main_board_codes()` + `get_latest_price()` + `stock_names_full.json`

### 2.2 L2 技术过滤

读取60日K线，计算5项技术指标，**满足任意≥2项即通过**：

| 指标 | 通过条件 | 权重 |
|------|----------|------|
| MA趋势 | MA5>MA10>MA20（多头排列）或 MA5向上（MA5 > MA5_5日前） | 1/5 |
| 成交量 | 近5日均量 > 0 且 量比(5日/20日) ≥ 0.8 | 1/5 |
| KDJ | KDJ金叉 或 K值 < 30（低位） | 1/5 |
| MACD | MACD金叉 或 DIF > DEA（红柱） | 1/5 |
| 涨停历史 | 近60日内有涨幅 ≥ 9.5% 的K线 | 1/5 |

**数据源**：`tdx_data_engine.get_kline(days=60)` + `TechnicalIndicators.ma/kdj/macd`

### 2.3 L3 多因子评分

读取60日K线，计算三维度因子，综合评分0-100分，保留Top 300只：

| 维度 | 满分 | 子因子 |
|------|------|--------|
| **技术面** | 40分 | MA多头排列(15) + 量价配合(10) + 突破20日高点(15) |
| **资金面** | 30分 | 量比(10) + 换手率近似(10) + 近3日量能递增(10) |
| **趋势面** | 30分 | RPS20(10) + 价格在MA60之上(10) + 突破60日线(10) |

**评分公式**：`factor_score = factor_technical + factor_fund + factor_trend`（上限100）

### 2.4 L4 AI深度分析

只对L3评分最高的**Top 80只**做深度分析：

| 分析项 | 说明 |
|--------|------|
| 三模型分析 | 涨停回调模型 / 箱体突破模型 / 量价突破模型，各输出匹配状态和独立评分 |
| AI综合评分 | 调用阶段2 `AICompositeScoreEngine.calculate()`，融合模型均分+因子评分 |
| 最终输出 | 综合评分、等级（S+/S/A/B/观察/风险）、交易建议 |

**K线周期**：120日（模型需要更长历史）

## 四、性能对比

### 4.1 与现有扫描器对比

| 指标 | 现有扫描器（固定500只） | 分层扫描器（全市场2232只） |
|------|------------------------|---------------------------|
| 扫描范围 | 固定500只 | 全市场2232只主板 |
| L1基础过滤 | 有（内嵌） | 独立层，1750只通过 |
| L2技术过滤 | 有（行为预筛） | 独立层，5项指标≥2通过 |
| L3多因子评分 | 强势主力评分 | 三维度因子评分，Top300 |
| L4 AI分析 | 固定100只 | Top80只，三模型+综合评分 |
| 总耗时 | 约2-5分钟 | **14.4秒** |
| 漏股风险 | 高（固定500只） | **低（全市场覆盖）** |

### 4.2 各层耗时占比

| 层级 | 耗时 | 占比 | 说明 |
|------|------|------|------|
| L1 基础过滤 | 9.0s | 62.7% | 逐只读取最新价格，IO密集 |
| L2 技术过滤 | 3.4s | 23.4% | 8线程并行读取60日K线+计算指标 |
| L3 多因子评分 | 1.6s | 11.1% | 8线程并行计算因子 |
| L4 AI深度分析 | 0.4s | 2.7% | 仅80只，三模型+综合评分 |

### 4.3 性能结论

- **总耗时14.4秒**，远低于3分钟目标（仅为目标的8%）
- L1是性能瓶颈（62.7%），可通过批量读取价格进一步优化
- L2/L3/L4并行效率高，合计仅5.4秒
- 全市场覆盖2232只，无漏股风险

## 七、后续优化方向

### 7.1 短期优化

1. **L1性能优化**：当前L1耗时9秒（62.7%），可通过批量读取价格或缓存最新行情减少IO
2. **L2过滤原因精确统计**：当前仅统计通过/未通过，可细化每个指标的未通过原因分布
3. **AI六维评分接入**：L4当前未接入AI六维评分（`ai_six_dim_score`为None），可调用 `SixDimensionScorer` 实时计算
4. **市场环境因子**：接入 `market_state_engine.py` 的市场状态评分，填充综合评分的 `market_environment` 因子

### 7.2 中期优化

5. **动态阈值调整**：根据市场环境自动调整L2通过条件数（牛市放宽、熊市收紧）
6. **L3因子权重优化**：基于历史回测数据用Walk Forward验证优化技术/资金/趋势权重
7. **板块过滤**：增加行业板块维度，避免候选股集中在单一板块
8. **结果缓存增量更新**：缓存L1/L2结果，盘中只重新计算变化的股票

### 7.3 长期优化

9. **L4 AI解释层**：接入Ollama本地大模型，对最终候选生成自然语言化理由
10. **组合构建**：从单股票评分扩展到股票组合构建，考虑相关性和仓位分配
11. **实时监控**：分层扫描结果接入实时监控，候选股出现信号时提醒
