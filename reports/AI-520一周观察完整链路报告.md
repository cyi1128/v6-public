## 八、D1-D5如何推进

### 8.1 交易日历判断

`ObservationService.get_trade_days_between(start_date, end_date)`:
- 排除周六周日
- 通过K线数据验证节假日
- 只计算真实交易日

### 8.2 每日推进逻辑

`ObservationService._update_single_task()`:
1. 计算 `day_number = get_trade_days_between(signal_date, trade_date)`
2. 如果 `day_number <= current_day` → 已更新过，跳过
3. 如果 `day_number > 5` → 标记为"已完成"
4. 获取该股票 `trade_date` 的真实K线
5. 计算 `pct_from_signal = (close - signal_price) / signal_price * 100`
6. 调用 `db.update_observation_daily()` 更新d{day_number}_date/price/pct
7. 写入 `observation_daily` 明细表
8. 更新max_return/min_return/max_drawdown

### 8.3 防重复机制

- 内存锁: `_daily_update_lock_table[trade_date]`
- 数据库锁: 检查 `observation_daily` 表是否已有该日期记录
- 同一天只执行一次每日更新

## 十、涨跌幅在哪里计算

**位置**: `services/observation_service.py` 的 `_update_single_task()`

```python
pct_from_signal = (close_price - signal_price) / signal_price * 100
```

**统一口径**:
- 基准价: `signal_price`（入选时价格，永不修改）
- 当前价: `close_price`（当日真实收盘价）
- 公式: `(当前价 - 基准价) / 基准价 × 100%`
- D1-D7每天独立计算，不累计

## 十一、最大涨幅在哪里计算

**位置**: `strategy/ai_520_database.py` 的 `update_observation_daily()`

```sql
UPDATE observation_pool SET
    max_return = COALESCE(
        (SELECT MAX(v) FROM (
            SELECT d1_pct as v UNION ALL SELECT d2_pct UNION ALL SELECT d3_pct
            UNION ALL SELECT d4_pct UNION ALL SELECT d5_pct UNION ALL SELECT d6_pct
            UNION ALL SELECT d7_pct
        ) WHERE v IS NOT NULL), max_return)
```

**计算方式**: 取D1-D7所有pct中的最大值。

## 十七、程序重启如何恢复

**恢复机制**:
1. 观察任务持久化在DuckDB数据库（`data/ai520_cache.duckdb`）
2. 程序重启后，`ObservationService.get_observing_tasks()` 从数据库读取所有 `status='观察中'` 的任务
3. 每日更新时，通过 `current_day` 字段判断已更新到第几天，避免重复更新
4. 防重复锁 `_daily_update_lock_table` 在重启后清空，但数据库级锁（observation_daily表记录）仍然有效

**测试验证**: 观察池423只任务在程序重启后仍然存在，每日更新只更新未更新的交易日。

---

## 十八、防重复机制

### 18.1 观察任务防重复
- `ObservationService.create_from_ai520_selection()` 检查 `code + signal_date` 是否已存在
- 同一天同一股票只创建一次观察任务

### 18.2 每日更新防重复
- 内存锁: `_daily_update_lock_table[trade_date]`
- 数据库锁: 检查 `observation_daily` 表是否已有该日期记录
- 单任务防重复: `day_number <= current_day` 时跳过

### 18.3 企业微信推送防重复
- `push_records` 表记录每次推送
- 同一时段同一天只推送一次
- 只有errcode=0才写入成功记录

## 十九、异常处理

### 19.1 行情获取失败
```python
kline = fetch_kline(code, days=30)
if not kline or len(kline) == 0:
    print(f"[OBS] {code} 无法获取K线数据")
    return {'updated': False, 'data_pending': True}
```
- 不崩溃，标记为 `data_pending`
- 下次更新时重试

### 19.2 单只股票更新异常
```python
except Exception as e:
    stats['errors'].append(f"{task.get('code')}: {e}")
    print(f"[OBS] {task.get('code')} 更新异常: {e}")
```
- 不影响其他股票更新
- 错误记录在stats中

### 19.3 企业微信推送失败
- `push_with_image_fallback()` 返回 `success=False`
- 不写入 `push_records` 成功记录
- 错误信息记录在返回结果中
