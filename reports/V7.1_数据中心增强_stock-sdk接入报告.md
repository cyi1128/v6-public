## 2. 数据源架构说明

### 2.1 整体架构

```
                    ┌─────────────────────────┐
                    │   RealtimeMonitorData   │  实时监控数据接口
                    │  (量价/分时/涨停信号)   │
                    └────────────┬────────────┘
                                 │
                    ┌────────────▼────────────┐
                    │   UnifiedDataProvider    │  统一数据调度器
                    │  (优先级自动切换+健康监控)│
                    └────────────┬────────────┘
                                 │
              ┌──────────────────┼──────────────────┐
              │                  │                  │
    ┌─────────▼────────┐ ┌──────▼───────┐ ┌────────▼────────┐
    │   TdxProvider    │ │StockSdkProvider│ │  AKShareProvider │
    │  (主数据源,优先级1)│ │(备用,优先级2)  │ │  (补充,优先级3)  │
    │  通达信本地.day   │ │ 东方财富公开API │ │   (预留扩展)     │
    └──────────────────┘ └───────────────┘ └─────────────────┘
              │                  │
    ┌─────────▼────────┐ ┌──────▼───────┐
    │data/tdx_data_    │ │ 东方财富API   │
    │engine.py (未修改) │ │ push2.east-  │
    │                  │ │ money.com     │
    └──────────────────┘ └───────────────┘
```

### 2.2 设计原则

1. **独立模块化**: 所有新增代码在 `data_center/` 目录下，与现有 `market/`、`data/` 模块完全隔离
2. **向后兼容**: 不修改任何现有文件，现有系统可继续正常运行
3. **插件化架构**: 基于 `DataProviderBase` 抽象基类，新增数据源只需继承并实现接口
4. **优先级切换**: 通达信(主) → stock-sdk(备用) → AKShare(补充)，自动故障转移
5. **真实数据**: 所有数据来自真实API，禁止使用模拟数据

## 3. stock-sdk接入方式和API说明

### 3.1 技术方案

**采用Python直接复现东方财富API**，不使用Node.js子进程调用stock-sdk npm包。

**选择理由**:
- 减少Node.js依赖，降低部署复杂度
- Python requests直接调用，性能更优
- 与现有项目技术栈一致（纯Python）
- 东方财富API完全公开免费，无需Token

### 3.2 东方财富API端点

| 功能 | 端点 | 方法 |
|------|------|------|
| 单只实时行情 | `http://push2.eastmoney.com/api/qt/stock/get` | GET |
| 全市场快照 | `http://push2.eastmoney.com/api/qt/clist/get` | GET |
| 日/周/月K线 | `http://push2his.eastmoney.com/api/qt/stock/kline/get` | GET |
| 分时数据 | `http://push2.eastmoney.com/api/qt/stock/trends2/get` | GET |

## 4. 自动切换机制说明

### 4.1 切换策略

`UnifiedDataProvider` 实现基于优先级的自动故障转移：

```
优先级1: 通达信 (tdx)
    ↓ 失败/不可用
优先级2: stock-sdk 东方财富 (stock_sdk)
    ↓ 失败/不可用
优先级3: AKShare (预留扩展)
    ↓ 全部失败
返回 None / 空列表，记录错误日志
```

### 4.2 切换触发条件

每次数据请求时，`_try_with_failover` 方法按优先级依次尝试：
1. 跳过已知不可用的数据源（但仍做一次快速健康检查，可能已恢复）
2. 调用目标方法，检查返回结果是否有效（非None、非空列表/字典）
3. 如果当前数据源成功且不是当前活跃数据源，记录切换事件
4. 全部失败时返回空结果并记录错误日志

### 4.3 健康监控

- **后台线程**: `UnifiedDataProvider-HealthMonitor`，每30秒检查一次
- **自动切回**: 主数据源（通达信）恢复后，自动切回主数据源
- **切换冷却**: 10秒冷却时间，避免频繁切换
- **切换历史**: 保留最近100条切换记录，含时间、来源、目标、原因

### 4.4 手动切换

```python
provider = UnifiedDataProvider()
provider.switch_provider('stock_sdk')  # 手动切换到stock-sdk
status = provider.get_provider_status()  # 获取所有数据源状态
history = provider.get_switch_history()  # 获取切换历史
```

## 5. 实时监控数据接口说明

### 5.1 RealtimeMonitorData 功能

`RealtimeMonitorData` 为V7.2盘口/分时实时信号增强提供基础数据层：

| 方法 | 功能 | 应用场景 |
|------|------|---------|
| `get_market_snapshot()` | 全市场实时快照 | 涨幅榜/跌幅榜/涨停扫描 |
| `get_watchlist_quotes(codes)` | 自选股实时行情 | 监控列表行情更新 |
| `get_volume_change(code)` | 量价变化检测 | 放量突破/缩量回踩提醒 |
| `get_intraday_data(code)` | 分时数据 | 分时急拉/急跌检测 |
| `detect_intraday_surge(code)` | 分时急拉/急跌检测 | 异动提醒 |
| `get_limit_up_status(code)` | 涨停状态 | 封单变化/开板监控 |
| `get_stock_monitor_signals(code)` | 综合监控信号 | AI实时监控中心输入 |
| `batch_monitor(codes)` | 批量监控 | 全市场信号扫描 |

### 5.2 量价变化检测逻辑

```
当前成交量 ÷ 近5日平均成交量 = 量比

量比 >= 2.0 且 涨幅 > 0 → 放量突破 (volume_breakout)
量比 <= 0.5 且 跌幅 < 0 → 缩量回踩 (volume_shrink_pullback)
量比 <= 0.5 → 缩量 (volume_shrink)
其他 → 正常 (normal)
```

### 5.3 分时急拉检测逻辑

```
取最近5根分时数据（约5分钟）
变化幅度 = (最新价 - 起始价) / 起始价 × 100%

变化幅度 >= 1% → 急拉 (is_surge)
变化幅度 <= -1% → 急跌 (is_plunge)
```

### 5.4 综合告警等级

| 等级 | 触发条件 |
|------|---------|
| normal | 无异常信号 |
| warning | 放量突破 或 分时急拉 |
| critical | 分时急跌 或 涨停 或 跌幅>=5% |

## 7. 与现有系统集成方式

### 7.1 独立运行（推荐）

`data_center/` 模块完全独立，可直接使用，不影响现有系统：

```python
from data_center import UnifiedDataProvider, RealtimeMonitorData

# 初始化统一数据调度器
provider = UnifiedDataProvider()

# 获取行情（自动切换数据源）
quote = provider.get_realtime_quote('600519')
kline = provider.get_kline('000001', days=120)

# 实时监控
monitor = RealtimeMonitorData(provider)
signals = monitor.get_stock_monitor_signals('600519')
```

### 7.2 与现有DataManager共存

现有 `market/data_manager.py` 和 `market/data_provider.py` 系统保持不变，继续服务于现有策略/回测/UI模块。`data_center/` 作为新增的独立数据层，主要服务于：
