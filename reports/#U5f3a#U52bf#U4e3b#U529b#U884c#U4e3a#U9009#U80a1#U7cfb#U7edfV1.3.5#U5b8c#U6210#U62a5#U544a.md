# 强势主力行为选股系统 V1.3.5 完成报告

## 详细筛选漏斗统计 + 数据健康检查

---

## 一、背景

V1.3.4修复了通达信K线解析格式（智能格式自动检测），旧缓存已清除。但用户反馈筛选不到股票，需要精确定位是哪一步过滤掉了所有股票。

V1.3.5增加完整的9步筛选漏斗统计和扫描前数据健康检查，让用户一眼就能看到死在哪一步、为什么过滤。

---

## 二、新增功能

### 1. 扫描前数据健康检查（自动执行）

在步骤2（全市场股票列表）之后、步骤3（主板过滤）之前，自动执行数据健康检查：

```
[DATA HEALTH] ========== 数据健康检查 ==========
[DATA HEALTH] 待扫描股票: 2232只 (抽样检查200只)
[DATA HEALTH] K线数据有效: 2209只 (close>0 且 open>0 且 high>0 且 low>0)
[DATA HEALTH] 价格异常(close<=0): 0只
[DATA HEALTH] 成交量异常(volume<=0): 23只
[DATA HEALTH] 缺少K线(根数<20): 0只
[DATA HEALTH] 最新K线日期: 20260820
[DATA HEALTH] 可参与筛选: 2209只
[DATA HEALTH] ==============================
```

**检查项**：
- K线数据有效性（close>0且open>0且high>0且low>0）
- 价格异常（close<=0）
- 成交量异常（volume<=0）
- 缺少K线（根数<20）
- 最新K线日期

**终止条件**：如果可参与筛选=0，直接终止扫描并提示"K线数据全部异常，请检查通达信盘后数据下载"。

**性能优化**：抽样检查最多200只，避免全量检查太慢。

### 3. L2预筛5个条件通过数统计

L2预筛完成后，抽样最多200只股票，统计5个条件各自的通过数：

- 条件1：近期涨幅>10%
- 条件2：成交量变化（缩量<0.8或放量>1.3）
- 条件3：大阳线（单日涨幅>5%）
- 条件4：横盘整理（近10日振幅<8%）
- 条件5：突破迹象（收盘价>近10日最高×0.98）

新增方法 `_layer2_check_conditions(code, days)` 返回各条件的True/False详情。

### 4. L3评分异常原因分类

L3深度分析的异常分为三类：
- 数据不足（kline_empty/data/empty/不足）
- 除以0（divide/zero/nan）
- 其他

在deep_worker中捕获异常时自动分类统计。

### 5. 模型平均分统计

漏斗统计中收集三个模型各自匹配的分数列表，计算并打印平均分：
- 涨停回调匹配：XXX只（平均XX分）
- 箱体突破匹配：XXX只（平均XX分）
- 量价突破匹配：XXX只（平均XX分）

### 6. 某步过滤后=0的警告

如果某一步过滤后数量为0，自动打印警告并提示可能的原因：
- 步骤2主板过滤=0 → 检查_filter_board逻辑（是否过滤了001开头等）
- 步骤3 L1过滤=0 → 检查行情数据（价格/成交量是否为0或None）
- 步骤4 L2预筛=0 → 检查预筛条件是否太严（5个条件OR逻辑）
- 步骤5 L3深度分析=0 → 检查评分计算是否有异常（数据格式/字段缺失）
- 步骤9最终池=0但L3>0 → 检查min_score阈值

### 7. 成交量单位检查

检查了4个文件中的volume单位转换：
- `strategy/base.py` — 无错误转换
- `strategy/models/volume_breakout.py` — 无错误转换
- `strategy/models/limit_up_pullback.py` — 无错误转换
- `strategy/models/box_breakout.py` — 无错误转换

通达信.day文件的volume单位是**手**（1手=100股），4个文件中均未发现 `volume * 100` 或 `volume / 10000` 等错误转换。

## 六、用户操作建议

1. **重新运行扫描**：控制台会先打印数据健康检查，确认K线数据有效性
2. **查看漏斗统计**：扫描结束后查看9步漏斗统计，定位是哪一步过滤掉了股票
3. **如果数据健康检查显示有效=0**：说明通达信K线数据有问题，需要在通达信软件中执行「盘后数据下载→日线数据」
4. **如果L2预筛=0**：查看5个条件统计，如果所有条件通过数都很低，说明市场整体处于弱势，不是程序bug
5. **如果L3深度分析=0但L2>0**：查看异常统计，如果数据不足/除以0很多，说明K线数据格式仍有问题
6. **如果最终池=0但L3>0**：说明评分都低于60分，可以考虑降低min_score阈值测试
