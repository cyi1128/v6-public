## 三、买点精度层设计

### 3.1 TOP1增强评分（100分制）

| 维度 | 满分 | 评分规则 |
|------|------|---------|
| 多头排列 | 20 | MA5>MA10得10分，MA10>MA20得10分 |
| 一阳穿均线 | 25 | 穿MA5得8分，穿MA10得8分，穿MA20得9分 |
| 缩量调整 | 15 | 量比<0.7得15分，<0.9得8分 |
| 温和放量 | 15 | 连续3日量比1.2-2.0得15分，当日得5分 |
| MACD红柱扩大 | 10 | MACD(12,26)红柱扩大得10分，(8,21)得6分 |
| KDJ低位金叉 | 10 | KDJ(9/13)低位金叉得10分，J<20得5分 |
| 板块同步 | 5 | 预留（需板块数据） |

### 3.2 TOP3增强评分（100分制）

| 维度 | 满分 | 评分规则 |
|------|------|---------|
| KDJ低位 | 20 | J<0得20分，J<20得15分，J<40得8分 |
| MACD双周期修复 | 25 | DIF>0+红柱扩大得13分，绿柱缩小得12分 |
| MA5站上MA10 | 15 | 刚金叉得15分，已在上方得8分 |
| 缩量回踩 | 15 | 回踩MA10+缩量得15分，仅缩量得7分 |
| 量能结构 | 15 | 连续放量得10分，缩量得5分 |
| 板块强度 | 10 | 预留（需板块数据） |

### 3.3 统一买点等级

| 等级 | 条件 | 含义 | 历史胜率参考 |
|------|------|------|------------|
| **S** | TOP1原始触发 + TOP3原始触发 | 双模型共振（最强信号） | 预计>55% |
| **A** | TOP1原始触发 | 突破确认型 | 52.76% |
| **B** | TOP3原始触发 | 提前埋伏型 | 52.42% |
| **观察** | TOP1增强分≥35 或 TOP3增强分≥35 | 接近触发，等待确认 | 待统计 |
| **过滤** | 增强分<35 | 条件不足 | - |

> **设计原则**：不过滤股票，所有信号保留，用评分排序。S/A/B级为精确触发，观察级为潜力候选。

### 3.4 评分分布实测（200只×5天=1000样本）

| 统计项 | TOP1增强分 | TOP3增强分 |
|--------|-----------|-----------|
| 均值 | 27.0 | 15.1 |
| 中位数 | 28.0 | 13.0 |
| 最大值 | 60 | 43 |
| ≥35分占比 | ~27% | ~3% |
| ≥40分占比 | ~7.6% | ~0.4% |

> 观察级阈值设为35分，约覆盖前27%的股票，每天全市场预计输出100-300只观察级信号，S/A/B级为稀有精确信号。

## 四、自动滚动优化闭环

### 4.1 每日自动流程

```
扫描信号 → 记录到DuckDB → 5日后自动复盘实际表现 → 每30天优化参数
```

### 4.2 信号数据库（v74_signals.db）

**表结构：signals**

| 字段 | 类型 | 说明 |
|------|------|------|
| signal_id | VARCHAR | 信号唯一ID |
| signal_date | VARCHAR | 信号日期 |
| stock_code | VARCHAR | 股票代码 |
| stock_name | VARCHAR | 股票名称 |
| model_type | VARCHAR | 模型类型（V74_S/A/B/观察） |
| grade | VARCHAR | 买点等级 |
| enhanced_score | DOUBLE | 增强评分 |
| top1_score / top3_score | DOUBLE | TOP1/TOP3分项评分 |
| buy_price | DOUBLE | 买入价格 |
| stop_loss / take_profit | DOUBLE | 止损/止盈价 |
| hold_days | INTEGER | 建议持仓天数 |
| status | VARCHAR | open/closed |
| actual_return_3d/5d/10d | DOUBLE | 实际3/5/10日收益(%) |
| max_profit / max_drawdown | DOUBLE | 最大盈利/回撤(%) |
| close_date | VARCHAR | 平仓日期 |

### 4.3 优化参数数据库（v74_optimization.db）

**表结构：optimizations**

| 字段 | 类型 | 说明 |
|------|------|------|
| optimization_date | VARCHAR | 优化日期 |
| model_type | VARCHAR | 模型类型 |
| factor_weights | VARCHAR | 因子权重（JSON） |
| best_take_profit | DOUBLE | 最优止盈(%) |
| best_stop_loss | DOUBLE | 最优止损(%) |
| best_hold_days | INTEGER | 最优持仓天数 |
| win_rate_30d | DOUBLE | 近30天胜率 |
| profit_ratio_30d | DOUBLE | 近30天盈亏比 |
| avg_return_30d | DOUBLE | 近30天均收益 |
| sample_count | INTEGER | 样本数量 |

### 4.4 自动反馈模块接口

| 函数 | 功能 |
|------|------|
| `record_signal(signal_data)` | 记录单个买点信号 |
| `record_signals_batch(signals_list)` | 批量记录信号 |
| `update_feedback(engine)` | 更新5日前信号的实际表现（3/5/10日收益、最大盈利/回撤） |
| `run_optimization(model_type, lookback_days)` | 基于近30天已关闭信号，网格搜索最优止盈/止损/持仓组合 |
| `get_current_params(model_type)` | 获取当前最优参数（无优化数据时返回默认8%/5%/5天） |
| `get_model_stats(model_type, days)` | 获取模型近期统计（胜率/均收益/最大盈亏） |
| `get_open_signals()` | 获取所有未平仓信号 |
| `daily_auto_flow(new_signals, engine)` | 每日一键流程：记录+复盘+优化检查 |

### 4.5 参数优化方法

- **止盈测试**：+5% / +8% / +10% / +15%
- **止损测试**：-3% / -5% / -8%
- **持仓测试**：3天 / 5天 / 10天
- **共48种组合**，模拟止盈止损触发后计算实际收益
- **综合评分**：胜率40% + 盈亏比30% + 均收益20% + 样本量10%
- **防过拟合**：样本<10不优化，使用默认参数

## 八、存在的问题

### 8.1 已知限制

1. **板块因子预留**：TOP1的"板块同步"(5分)和TOP3的"板块强度"(10分)当前为预留项，得分为0。需要接入板块数据后才能激活，这会使当前评分上限降低5-10分。

2. **S/A/B级信号稀有**：原始模型触发条件（TOP1: 多头排列+一阳穿均线+缩量；TOP3: KDJ低位+双MACD修复）非常严格，全市场每天可能0-5只。观察级（增强分≥35）是主要输出层级。

3. **自动优化样本不足**：刚上线时信号数据库样本少，参数优化使用默认值。需要实盘运行1-2个月积累足够样本后，自动优化才能发挥作用。

4. **股票名称映射**：`get_stock_list_with_names()`返回格式为list，已做兼容处理，但部分股票名称可能显示为代码。

### 8.2 修复记录

- **Bug修复**：`stock_names`类型不匹配（list vs dict）导致`scan_stock`静默异常返回空列表，已修复为兼容list[dict]/dict/tuple多种格式。
- **阈值调整**：观察级阈值从60分下调至35分，因增强评分实际最大值约60分（受互斥条件限制），60分阈值永远无法触发。

## 十、使用指南

```python

from strategies.v74_buy_point_layer import V74BuyPointLayer

    print(f"[{r['grade']}] {r['code']} {r['name']} "
```

## 十一、总结

V7.4完成了从"策略模型"到"实盘闭环系统"的关键升级：

1. **买点精度层**：在V7.3验证通过的TOP1/TOP3模型基础上，增加7维度+6维度增强评分，实现S/A/B/观察四级输出，不过滤只排序

**核心设计哲学**：52%胜率+正盈亏比+稳定性，比70%胜率但没信号更适合实盘。V7.4不追求极致胜率，而是通过精度层排序和自动闭环优化，在可交易信号数量和胜率之间取得平衡。
