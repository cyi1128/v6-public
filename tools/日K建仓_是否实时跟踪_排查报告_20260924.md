# 一、结论

**不是实时跟踪。** 日K建仓是「盘前/盘后扫描一次 → 写库 → UI 只读库」的**静态快照**，
三个层面都不实时：

| 层面 | 实际情况 | 代码位置 |
|---|---|---|
| 入选名单 | 静态，今早 08:46 扫描写入 | `_daily_fetch_and_calc` → `query_signals()` → 读 `band_pattern.db` |
| 「现价」 | **昨天(9/23)的收盘价**，不是实时价 | `'price': s.get('push_price')` |
| 「涨跌幅」 | **9/23 的涨跌幅**，不是实时涨幅 | `'pct': s.get('push_pct')` |
| UI 刷新 | 5 分钟一次，但读的是同一份静态数据 | `_daily_timer.start(300000)` |

## 2.3 UI 刷新机制：5 分钟一次，但内容不会变

```python
# _switch_tab (1330-1360)：只有切到「日K建仓」Tab 才启动
if not self._daily_timer.isActive():
    self._daily_timer.start(300000)      # 5 分钟
if not self._daily_gs_timer.isActive():
    self._daily_gs_timer.start(900000)   # 15 分钟（金铲子弹窗）
QTimer.singleShot(0, self._daily_refresh)

# 切回「分时做T」
self._daily_timer.stop()                 # ← 完全停止
self._daily_gs_timer.stop()
```

`_daily_refresh` 每 5 分钟重新 `query_signals()` 读**同一个 DB** → 库不变则表格不变。
**只有重新跑「盘后扫描_波段四模式.bat」才会变化。**

# 三、附带发现：178 条展示记录里，173 条已过期

`expire_overdue()`（`band_pattern_engine.py:224-243`）的 SQL 写死了 `pattern_id = 4`：

```python
"UPDATE pattern_record SET signal_level=?, invalid_reason=?, updated_at=? "
"WHERE pattern_id = 4 AND valid_until != '' AND valid_until < ? "
"AND signal_level IN (?,?,?)"
```

**→ 模式一/二/三 永远不会自动失效。**

而 UI 的展示条件是 `signal_level in ('建仓触发','等待确认')`（`atr_t_widget.py:1792`），
于是：

| 模式 | 状态 | 条数 |
|---|---|---|
| 模式1 跳空回踩 | **已过期** | **109** |
| 模式2 大阳整理 | **已过期** | **60** |
| 模式3 底部横盘 | **已过期** | **4** |
| 模式4 周K确认 | 有效 | 5 |
| | **合计** | **178** |

**173/178 = 97% 是过期信号，仍在表格里显示。**

样例：

```
000576 甘化科工  模式1  base_date=2026-08-27 valid_until=2026-09-23  等待确认
000620 盈新发展  模式2  base_date=2026-09-08 valid_until=2026-09-23  建仓触发  ← 过期还标"建仓触发"
000628 高新发展  模式1  base_date=2026-08-24 valid_until=2026-09-21  等待确认  ← 过期3天
000728 国元证券  模式1  base_date=2026-08-25 valid_until=2026-09-22  等待确认
```

这正是你之前说的「**基准日太久，行业都过去了**」——代码级原因就在这里。

# 四、要不要修？请你定

这三件事都涉及策略取舍，**我没有动**：

## ① 日K建仓主表要不要接实时行情？

- 现状：显示昨天收盘价，红绿方向都可能是反的
- 改法：`_daily_fetch_and_calc` 里像分时做T 那样批量拉 `get_realtime_quotes_http`
- 代价：178 只一次批量请求（实测 10 只 0.16 秒，178 只预计 1~2 秒，放后台线程即可）
- **建议：接。** 表里列名就叫「现价/涨跌幅」，显示昨天的值会误导决策

## ② 模式一/二/三 要不要也自动失效？

- 现状：265 条永不失效，97% 的表格被过期信号占满
- 改法：`expire_overdue()` 去掉 `pattern_id = 4` 限制
- 风险：表格会从 178 条掉到 **5 条**（只有模式四有效）——数量骤减
- **替代方案**：不删，但加「已过期」标记 + 默认不显示，需要时手动展开

## ③ 「盘中监控」标签要不要改？

- 现状：数据是静态的，标签却写「盘中监控」
- 改法：改成「盘后扫描 · 数据日期 09-23」之类，如实反映
