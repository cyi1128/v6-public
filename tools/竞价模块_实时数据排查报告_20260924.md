# 二、「不是实时数据」——根因（含铁证）

## 2.1 根因

`refresh()` 的 **snapshot 分支**（`AUCTION_END` 之后，约 363~376 行）：

```python
if self._rows:
    self.title_label.setText(f'⚡ 竞价 TOP{len(self._rows)}（竞价已结束·复盘）')
    self.set_status(f'竞价已结束 · {len(self._rows)}只 · 复盘')
else:
    ...
```

而实时行情刷新挂在 **`_render_rows()` 末尾**（1164 行）：

```python
self._fetch_realtime_from_tencent()   # 补当前涨幅 / 当前价
```

**两条线永远接不上**：9:30 之后每 60 秒 `refresh()` 一次，只要 `self._rows` 非空，
就只改标题和状态栏，**从不调用 `_render_rows()`** →
`_fetch_realtime_from_tencent()` **一次都不会执行** →
表格里的「当前涨幅 / 当前价」永远停在 9:29 的快照值。

## 2.2 动态实证（不是读代码猜的）

`tools\_prove_auction_frozen.py`，塞入 9:29 死数据后模拟 9:56 连续 refresh 3 次：

```
=== 模拟 9:56（snapshot 阶段）连续 3 次 refresh() ===
  第1次 refresh 后: _render_rows=0  _fetch_realtime=0
  第2次 refresh 后: _render_rows=0  _fetch_realtime=0
  第3次 refresh 后: _render_rows=0  _fetch_realtime=0
结论: _render_rows 次数 = 0，实时行情次数 = 0
      表格第4列(当前涨幅) = '+2.10% 〔快照〕'   ← 9:29 死数据
      表格第6列(当前价)   = '10.55'             ← 9:29 死数据
```

对照：同一时刻接口真实值 600650 = **10.50 / +1.84%**，而表格显示 10.55 / +2.10%。

## 2.3 修复（3 处 + 1 处口径）

| # | 位置 | 改动 |
|---|---|---|
| A | `refresh()` snapshot 分支 | `_rows` 非空时补调 `_fetch_realtime_from_tencent()`——**只冻结入选名单，不冻结行情** |
| B | `_fetch_realtime_from_tencent` | 原来自称"异步"实为**主线程同步网络调用**（每 60s 卡一次 UI）→ 改 `run_async` 真后台线程；拆出 `_fetch_rt_quotes`（线程内取数）+ `_apply_rt_quotes`（主线程写表） |
| C | `_apply_rt_quotes` | 只有真拿到实时价(`price>0`)才打 `rt_live=True` 并清〔快照〕；没拿到**保持原样，绝不把 9:29 旧值伪装成实时** |
| C2 | `_render_rows` | `_is_snapshot = (not r.get('rt_live')) and _is_auction_t(_cur_time)` |

# 三、「9:15 就开始筛选，为什么没执行」——它执行了

## 3.1 铁证：今天第一笔数据是 09:25:06

查 `data\cache\auction_tracking.duckdb` 的 `auction_tracking` 表，今天（2026-09-24）记录：

| 600743 | 华远控股 | **2026-09-24 09:25:24** |

**9:15~9:25 一条都没有。**

## 3.2 为什么 09:25:06 恰好证明"模块一直在跑"

新浪 **9:25:00** 才发布竞价价，模块下一次轮询约在 **09:25:05**，立刻抓到 → 09:25:06 落库。
若模块是 09:25:30 才启动，第一条必然是 09:25:31。**时间差反证轮询一直在跑。**

## 3.3 模块确实是"开机即跑"，不是懒加载

`ui\battle_console_v2.py:6597`：

```python
self.home_page = BattleConsoleHome()      # 主窗口构建时立即创建
self.tabs.addTab(self.home_page, '🤖 清一盘')
```

→ `AuctionFilterWidget.__init__` 里 `self.start_refresh(60000)` 随程序启动即生效，
**每 60 秒自动刷新**（基类 `base.py:322 start_refresh` 实现正常）。

## 3.4 所以真实原因是

**9:15~9:25 新浪接口整页 `changepercent=0`（不发布竞价价），
模块每 60 秒都在跑，但每次都筛出 0 条，页面上自然什么都没有。**

已修：接入腾讯涨幅榜作为 **9:25 前兜底源**（口径保护：只在 9:25 前启用）。
**但改动必须重启程序才生效**，而今天主程序 9:43:18 才重启，已经错过窗口。

# 四、为什么「每天都要出问题」——4 个系统性原因

1. **9:15~9:25 新浪无竞价价** → 模块在跑但结果为空。（已修：腾讯兜底）
2. **9:30 后行情列被永久冻结** → 看着像死数据。（本次已修）
3. **程序必须在 9:25~9:30 之间处于运行状态**，否则当天没有任何快照，
   之后只能读到旧快照或空白。（未修，见第五节）
4. **所有改动必须重启程序才生效**。主程序加载的是旧代码，
   这是"改了没用 / 打开程序根本没变化"观感的主要来源。

## 5.2 快照回退会把昨天的股票当今天展示

`refresh()` snapshot 分支：

```python
today = now.strftime('%Y-%m-%d')
if not self._restore_auction_snapshot(today):
    latest = _trade_cal.get_latest_trading_date(now)
    if latest != today:
        self._restore_auction_snapshot(latest)      # ← 会加载昨天 15 只
```

今天有快照所以走了正确分支；但**一旦当天没跑成**，页面会直接显示
昨天（9/23）的 15 只竞价股。状态栏有写日期，但很容易看漏。
