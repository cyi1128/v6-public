## 三、为什么整段注释，而不是只注释 addTab

原始代码（L6615-6625，现已注释）：

```python
print("[主窗口] 创建选股雷达页（主力启动+AI520）...", flush=True)
self.radar_page = QWidget()
_radar_lay = QVBoxLayout(self.radar_page)
_radar_lay.setContentsMargins(0, 0, 0, 0)
self._radar_inner = BattleConsoleHomeV2()      # ← 重量级组件，在这里被创建
_radar_lay.addWidget(self._radar_inner)
self.tabs.addTab(self.radar_page, '🎯 选股雷达')   # ← 如果只注释这一行…
print("[主窗口] 选股雷达页已添加", flush=True)
```

**如果只注释最后那行 `addTab`**，`BattleConsoleHomeV2()` 照样会被实例化 —— 界面虽然不显示，但：
- 启动时白耗时间（要构建 QScrollArea + 大量子控件）
- **闪退风险照旧存在**

所以整段一起注释，**根本不创建这个对象**。

### 额外收益：消掉一个闪退源

原代码自己的注释（L6616-6618）就写着：

> 【V2.9.6修复】Qt 6.11 + Python 3.14 下，大型 QWidget 子类（BattleConsoleHomeV2，含 QScrollArea + 大量子控件）直接作为 QTabWidget 页面时，窗口最大化/缩放触发 **C++ 层渲染段错误（0xC0000005）**

`0xC0000005` 就是你之前遇到的闪退日志：

```
程序异常退出，错误码: -1073740791
```

`-1073740791` 转成十六进制正是 **0xC0000005**。移除这个页面，等于**消除一个已知的闪退来源**。

## 四、为什么必须同时改 `_connect_signals`

原始代码（L6725-6727，现已改）：

```python
_radar_src = getattr(self, '_radar_inner', None) or self.radar_page
```

`_radar_inner` 属性不存在时，`getattr` 返回 `None`，`or` 会**继续求值** `self.radar_page` → 而它也不存在 → **AttributeError**。

改成：

```python
_radar_src = getattr(self, '_radar_inner', None)
if _radar_src is not None:
    _radar_src.stock_clicked.connect(self._show_stock_detail)
```

这样即使以后恢复这个页面，代码也照样能跑。
