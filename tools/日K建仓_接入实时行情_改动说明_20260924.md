# 二、设计要点（为什么这么写）

| 要点 | 做法 | 原因 |
|---|---|---|
| 不卡 UI | 取数留在 `_daily_fetch_and_calc`，它由 `_daily_refresh` → `run_async` 跑在**后台线程** | 178 只实测 0.23 秒，但网络抖动时也不该阻塞界面 |
| 不置 0 | `if _p <= 0: continue` 保留 DB 原值 | 停牌/接口失败时，宁可显示旧价，也不能把「现价」变成 0 或 `--` |
| 线程安全 | 后台线程只写 `self._daily_rt_stat`（普通属性赋值），状态栏在主线程 `_daily_on_loaded` 里写 | 不在后台线程调 UI 方法 |
| 兜底 pct | `pct_chg` 缺失时用 `(price - last_close)/last_close*100` 现算 | 接口偶发缺字段时不显示 0% |
| 全时段生效 | 不做交易时段判断 | 盘后接口给的就是当日收盘价，覆盖后同样正确 |

**没有改动的地方**：分时做T（`_fetch_and_calc` / `_render_hold_table`）、日K金铲子（`_daily_check_golden_spade`）、
表头 10 列、`_daily_render_table` 渲染逻辑、`_daily_timer` 5 分钟周期 —— **全部原样**。
