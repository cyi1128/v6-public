# 📈 市场节奏模块 — 三 Tab 思路逻辑

> 核对日期：2026-10-09 ｜ 全部内容按实际代码逐条摘出。
> 这是「盘中机会 + 金铲子 + 板块异动」三个旧模块**合并升级**后的唯一模块。

---

## 0. 它要回答的问题

老「板块异动」只能列一堆**已经涨停**的票，你只能干看。现在这个模块要回答四件事：

1. **市场在干嘛** —— 是轮动还是持续
2. **板块和个股怎么联动** —— 谁带的谁
3. **哪天涨了哪个题材** —— 题材记忆（近 10 个交易日）
4. **题材里的强势股是谁** —— 龙头 + 梯队

而且必须给出**可以下手**的票，不是涨停名单。

## 3. Tab1「市场节奏」`market_rhythm_engine.py`

### 3.1 输入与预过滤

- 读最近 `MEMORY_DAYS + 5 = 15` 个交易日
- **只留主板**：`is_main_board()` = 沪 600/601/603/605 + 深 000/001/002/003
- 为什么要这一条：创业板/科创板是 20cm/30cm，混进来会让板块「均涨幅」失真（实测算出 15%），而且你的口径一直是只看主板

### 3.2 题材拆词 `split_reason()`

`'AI漫剧+影视院线+北京国资'` → `['AI漫剧', '影视院线', '北京国资']`

| 处理 | 内容 |
|---|---|
| 分隔符 | `[+＋·、/]` |
| 去引号 | `“华”字辈` → `华字辈` |
| 丢**停用词** `STOPWORDS` | 全产业链／产业链／供应链／产品升级／产业升级／战略合作／技术领先／行业龙头／细分龙头／市场份额／业务转型／国产替代／自主可控／专精特新／数字化转型／降本增效／完成／布局 …（共 **35 个**）<br>→ 这些是**描述性短语，没有炒作含义**，拆出来直接不当题材用 |
| 长度 | `KW_MIN, KW_MAX = 2, 12` |

### 3.3 属性词 vs 真题材

`ATTRIBUTE_WORDS`（**40 个**）= 财务/股权属性，**不是炒作题材**：业绩增长／半年报增长／业绩预增／扭亏为盈／国企改革／股权转让／重大重组／高送转／分红／中标／订单／回购／增持／解禁／次新股／超跌反弹／破净 …

处理原则：**不删，只降权排到最后** ✓

### 3.4 状态机（8 个状态）

先算三个量：

| 量 | 定义 |
|---|---|
| `n_today` | 今日该题材涨停家数（主板） |
| `n_prev` | **昨日**该题材涨停家数 |
| `run` | 从今天往回，连续「≥2 家」的天数 |
| `pre3_max` | 前 3 个交易日（**不含今天、不含昨天**）里的最大家数 |

判定：

```
若 n_prev >= 2：
    run >= 3  →  今<昨 ? 📉退潮 : ⚡持续
    run == 2  →  今<昨 ? 📉退潮 : 🔥发酵中
    否则      →  ⚡持续
    叠加：n_today >= 8 且 n_today >= n_prev  →  🚀高潮
否则（昨天 0 或 1 家，今天是新接上来的）：
    pre3_max >= 2 ? ♻️复活 : 🆕首日启动
```

| 状态 | 配色（`STATE_COLOR`） |
|---|---|
| 🆕首日启动 | 蓝 |
| ♻️复活 | 紫 |
| 🔥发酵中 / ⚡持续 | 红 |
| 🚀高潮 | 橙 |
| 📉退潮 | 绿 |
| 💀熄火 / ·零星 | 灰 |

> **这是本模块最关键的一处修正。** 原版用「前 3 日家数」判连续性，导致**中间断档又被接起来**的题材被误标成「⚡持续」。
> 实测案例：AI漫剧 09-30 有 2 家 → 10-08 断档 → 10-09 又 4 家，原版标「持续」✗ 现在**必须看昨日家数**，正确标成「♻️复活」✓

### 3.5 排序键

```python
boards.sort(key=lambda b: (1 if b['is_attribute'] else 0,   # 真题材优先，属性词沉底
                           _STATE_RANK.get(b['state'], 9),   # 发酵/持续 0 > 首日/复活/高潮 1
                                                             #   > 退潮 3 > 零星 4 > 熄火 5
                           -b['count'],                      # 家数多优先
                           -b['avg_pct']))                   # 均涨幅高优先
```

### 3.6 龙头与梯队

```python
ladder = sorted(members, key=lambda r: (-(r['lbc'] or 1), _time_key(r['time'])))
```

**连板身位优先 → 首封时间早优先** ✓ 龙头 = `ladder[0]`，梯队 = 前 4~5 只。

### 3.7 同簇题材 `cluster_of()`（数据驱动）

不维护映射表。做法：算该题材股票集合与**其它每个题材**的交集大小，取共享股票最多的前 3 个。

作用：把 `AI漫剧 / 微短剧 / AI短剧` 这种拆碎的同一主线重新看出来。
实测：`创新药 -> 减肥药、抗生素、核医药` ✓

### 3.8 主线归并 `MAINLINE` / `mainline_of()`

15 条主线，**顺序 = 从具体到泛指，命中即止**：AI传媒／AI算力／机器人／半导体／新能源车／光伏储能／医药／军工／网络安全／国企改革／农业／消费／金融／地产基建／AI应用。

作用：交易员看盘不会把「AI漫剧 / AI短剧 / 微短剧 / AI视频」当四个方向 —— 它们是一条线。归并后拼成 `A/B/C(N家)`，最多 3 条。

> 注意：**只用于「主线」辅助列和轮动摘要**，主表仍按具体题材列 ✓

### 3.9 轮动方向

| 分类 | 定义 |
|---|---|
| **新进** `new_in` | 今日 ≥2 家 **且** 昨日 <2 家 |
| **退潮** `fade` | 昨日 ≥2 家 **且** 今日 <2 家 |
| **熄火** `dead` | 昨日 ≥2 家 **且** 今日 **0 家** |

再按主线归并成摘要：

```
两者都有 → 资金从 A、B 切向 C、D
只有新进 → 新方向进场：…
只有撤离 → 资金撤离：…
都没有   → 没有明显切换，延续昨日结构
```

**实测输出**（2026-10-09）：`资金从 磷酸铁锂/锂电池(4家)、营收增长(2家) 切向 AI漫剧/AI短剧/微短剧(8家)、AI安全/AI应用(4家)`

### 3.10 题材记忆矩阵

`memory` = 近 10 个交易日的「日期 × 题材」家数序列（取前 12 个真题材）。
UI 放在「**近10日家数**」列，旧→新，0 显示为 `·` ✓

### 3.11 Tab1 列定义

```
题材 | 主线 | 状态 | 今/昨 | 连续 | 最高板 | 龙头 | 题材内强势股 | 近10日家数 | 同簇题材
GRID = [112, 84, 98, 62, 48, 52, 122, 330, 205, 180]   # 强势股列 Stretch
```

概况条：`数据：<日期> ｜ 涨停 N 家 ｜ 最高 M 板 ｜ 板块 K 个 ｜ 近10日家数：MMDD→MMDD（旧→新）`
黄底条：`轮动方向：…`
点「**龙头**」列 → 跳个股分析 ✓

## 4. Tab2「可介入」`board_anomaly_engine.py`

### 4.1 板块聚合（两个维度）

| 维度 | 聚合方式 |
|---|---|
| **题材** | 涨停原因拆词后按词聚合，`≥2 家`才算 |
| **行业** | 涨停股 `industry` 字段聚合，`≥2 家`才算；额外算该行业**全市场**均涨幅（`all_avg_pct` / `all_count`） |

### 4.2 龙头判定 `_dragon_key()`

**口径对齐业内主流**：

```
升序键 = (有无首封时间, -(连板身位), 首封时间, -(封单额), -(今日涨幅))
             ↑              ↑            ↑          ↑
        无历史的排最后   权重最高    同身位谁先封   再比封单额   兜底
```

显示为「龙一 / 龙二 / 龙三」—— **不用 🥇🥈🥉 图标**（你明确拒绝过）✓

### 4.3 「可介入」候选口径（5 条硬门槛）

| # | 条件 | 阈值 |
|---|---|---|
| 1 | 未涨停 | 在涨停池里 → 它是龙头，不是介入标的 |
| 2 | 涨幅 | `1.0% ≤ pct < 9.0%`（要有资金进，但还没封板才买得进） |
| 3 | 股价 | `≥ 6.0 元`（你既定要求） |
| 4 | 非 ST | 名字含 `ST` → 剔除 |
| 5 | 量比 | `≥ 1.2`（取不到时不拦） |
| 6 | **MA20** | `现价 < MA20` → 剔除；**在 MA20 上**顺便算出「距MA20 涨幅%」 |

按涨幅降序，每个板块最多展示 **5 只**（`_PICK_TOP = 5`）。

成分股池：板块名 → 代码集合，来自涨停库历史积累（`_load_pools`），所以「国企改革」这类大板块能到 250+ 只；用**查表**而非网络请求，开销极小。

### 4.4 缓存与容错

| 项 | 值 | 说明 |
|---|---|---|
| 结果缓存 `_TTL` | **90 秒** | 原 300 秒，但候选是「现在能不能买」，盘后固定、盘中有变 |
| 实时行情 `_RT_TTL` | 60 秒 | 腾讯 `qt.gtimg.cn`，全市场 1.8 秒 |
| 成分池 `_POOL_TTL` | 600 秒 | 涨停库历史积累，变化慢 |
| MA20 | 600 秒 | DuckDB 窗口函数一条 SQL，3000+ 只 **0.04 秒** |
| MA20 失败 | 返回 `{}` | 调用方**不做过滤** —— 既不误杀，也不会让主流程失败 |

### 4.5 Tab2 列定义

```
板块/题材 | 家数 | 均涨幅 | 龙头 | 可介入 | 成分股
P_GRID = [104, 46, 100, 150, 340, 240]   # 成分股 Stretch
```

概况条：`涨停名单：MM-DD ｜ 今日涨停 N 家 ｜ 可介入 M 只（K 个板块）｜ 可介入口径：非涨停｜涨幅1~9%｜量比≥1.2｜现价≥MA20`
点「**龙头**」跳龙头、点「**可介入**」跳候选第一名 ✓

> 实测：Tab1 说「涨停 62 家」，Tab2 说「今日涨停 69 家」—— **都对**。
> Tab1 的引擎已按主板过滤（62），Tab2 的不含主板过滤（69）。差的就是非主板那 7 只。

## 5. Tab3「追踪」`picks_tracking_service.py`

### 5.1 入库（`_persist_picks`）

| 条件 | 值 |
|---|---|
| 交易日 | `is_trading_day()` |
| 时间 | **≥ 15:00** |
| 频率 | 每天一次（`_persist_date`） |
| 幂等 | 同一 `(交易日, 代码)` 不重复；**P0 一旦落库不再被覆盖** |

**为什么必须 15:00 之后才写：** P0（入选价）要取**当日收盘价**，盘中价会虚增/虚减收益。

### 5.2 收益计算 `fetch_tracking()`

```
r5   = (bars[idx+5]  - base_price) / base_price × 100
r30  = (bars[idx+30] - base_price) / base_price × 100
cum  = (当前价     - base_price) / base_price × 100
```

细节处理：

- **当前价**：优先实时行情，其次最近收盘
- **入选当天 kline 还没落盘时**，用实时行情**拼一根K线**补上 —— 否则定位不到 `idx`，T+5/T+30 永远显示「持有中」
- **累计盈亏**：当天刚入选的**不算**（持有期为 0，收益必然 0，计进去会被当成「没赢」压低胜率）→ 显示「持有中」
- 绝对值 < 0.005% 归为 0
- 追踪表保留 **100 自然日**（约 70 个交易日）

### 5.3 统计 `summarize()`

**样本为 0 的项返回 `None`**，界面显示「--」而不是 0 ✓（不会把「没数据」伪装成「0%胜率」）

### 5.4 当前真实成绩

```
5 日   n=4785   胜率 41.0%   均值 -1.26%   最好 +61.10%   最差 -42.83%
30 日  n=2805   胜率 43.7%   均值 -0.06%   最好 +146.83%  最差 -49.75%
累计   n=4822   胜率 35.5%   均值 -2.32%   最好 +167.82%  最差 -53.07%
```

> 这套「非涨停 + 涨幅1~9% + 量比≥1.2 + 现价≥MA20」的口径**偏弱**，胜率在 41~44%。数据摆在这里，是否调口径你定。

### 5.5 历史回填 `backfill_history()`

从 `kline_cache` + 涨停库**反算过去 70 个交易日的可介入标的**，把历史成绩补出来（`BACKFILL_DAYS = 70`，板块内 ≥2 家涨停才算异动）。

## 7. 刷新与并发

| 项 | 值 |
|---|---|
| 自动刷新 | **60 秒**（`start_refresh(60000)`） |
| 首次刷新 | `QTimer.singleShot(500, refresh)` |
| 并发保护 | `self._lock` + `self._busy` —— 上一轮没跑完直接 return，不排队堆积 |
