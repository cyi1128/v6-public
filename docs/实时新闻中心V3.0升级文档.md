# 实时新闻中心 V3.0 全量升级 — 技术文档

> 模块路径：`news_center/`  
> UI集成：`ui/battle_console_v2.py` → `NewsPage` 类

## 一、模块架构总览

```
news_center/
├── __init__.py              # 模块导出入口
├── news_config.py           # 全局配置（所有可调整参数）
├── news_sources.py          # 多源新闻接入与统一格式化（6个数据源）
├── news_dedup.py            # 三层智能去重引擎 + 24小时已展示缓存
├── news_refresh_engine.py   # 定时刷新引擎（智能启停 + 后台线程）
└── investment_calendar.py   # 投资日历数据提供者（5大维度）
```

**数据流**：`刷新引擎` → `多源并行拉取` → `三层去重` → `增量追加UI` → `标记已展示缓存`

## 二、配置项说明文档

所有配置集中在 `news_center/news_config.py`，可通过 `config/news_center_config.json` 外部覆盖。

### 2.1 数据源配置 (`sources`)

| 参数 | 默认值 | 说明 | 建议值 |
|------|--------|------|--------|
| `juchao.enabled` | `true` | 巨潮资讯（上市公司官方公告）P0 | 保持开启 |
| `juchao.authority` | `100` | 权威度评分，去重时保留高分来源 | 100 |
| `akshare.enabled` | `true` | AkShare财经新闻（财联社电报）P1 | 保持开启 |
| `akshare.authority` | `80` | 权威度 | 80 |
| `ths.enabled` | `true` | 同花顺7x24快讯 P1 | 保持开启 |
| `ths.authority` | `75` | 权威度 | 75 |
| `eastmoney.enabled` | `true` | 东方财富财经要闻 P2 | 保持开启 |
| `eastmoney.authority` | `70` | 权威度 | 70 |
| `sina.enabled` | `true` | 新浪财经新闻 P2（保留原有源） | 保持开启 |
| `sina.authority` | `65` | 权威度 | 65 |
| `sina_7x24.enabled` | `true` | 新浪7x24实时新闻 P2 | 保持开启 |
| `sina_7x24.authority` | `60` | 权威度 | 60 |

**权威度排序**：巨潮(100) > AkShare/财联社(80) > 同花顺(75) > 东方财富(70) > 新浪(65) > 新浪7x24(60)

### 2.2 自动刷新配置 (`refresh`)

| 参数 | 默认值 | 说明 | 建议值 |
|------|--------|------|--------|
| `active_interval` | `180` | 新闻页可见时刷新间隔（秒），默认3分钟 | 120-300 |
| `background_interval` | `600` | 切换到其他Tab时刷新间隔（秒），默认10分钟 | 600-900 |
| `initial_delay` | `2` | 启动后首次刷新延迟（秒） | 2-5 |
| `incremental_limit` | `80` | 每次增量刷新拉取条数 | 50-100 |
| `full_load_limit` | `200` | 首次全量加载条数 | 150-300 |
| `max_cached_news` | `500` | 内存最大保留新闻条数 | 300-800 |
| `cache_ttl_hours` | `24` | 已展示新闻缓存池有效期（小时） | 24 |
| `new_highlight_duration` | `8` | 新增新闻高亮持续时间（秒） | 5-15 |

### 2.3 去重配置 (`dedup`)

| 参数 | 默认值 | 说明 | 建议值 |
|------|--------|------|--------|
| `similarity_threshold` | `0.85` | 标题相似度阈值（≥0.85判定重复） | 0.80-0.90 |
| `keyword_match_min` | `2` | 关键词二次校验最小匹配数 | 2 |
| `event_window_minutes` | `30` | 事件级去重时间窗口（分钟） | 30-60 |
| `enable_exact_dedup` | `true` | 第一层：精确去重开关 | true |
| `enable_similarity_dedup` | `true` | 第二层：相似度去重开关 | true |
| `enable_event_dedup` | `true` | 第三层：事件级去重开关 | true |

### 2.4 投资日历配置 (`calendar`)

| 参数 | 默认值 | 说明 | 建议值 |
|------|--------|------|--------|
| `display_days` | `7` | 默认展示未来天数 | 7 |
| `auto_update_hour` | `8` | 每日自动更新时间（小时，开盘前） | 8 |
| `cache_ttl_hours` | `12` | 日历数据缓存有效期（小时） | 12 |

### 2.5 性能配置 (`performance`)

| 参数 | 默认值 | 说明 | 建议值 |
|------|--------|------|--------|
| `max_refresh_duration_sec` | `2` | 单次全量刷新耗时上限（秒） | 2 |
| `max_daily_cache_mb` | `50` | 单日新闻缓存内存上限（MB） | 50 |
| `parallel_fetch_workers` | `5` | 并行拉取线程数 | 3-6 |
| `source_fail_threshold` | `3` | 单源连续失败次数后临时降级 | 3 |
| `source_cooldown_rounds` | `1` | 降级后冷却轮数（下一轮自动重试） | 1 |

## 三、接入接口清单与调用方式

### 3.1 新闻数据源接口

| 数据源 | 接口地址/方式 | 方法 | 优先级 | 超时 |
|--------|--------------|------|--------|------|
| **巨潮资讯** | `http://www.cninfo.com.cn/new/hisAnnouncement/query` | POST | P0 | 10s |
| **AkShare财联社** | `ak.stock_info_global_cls(symbol="全部")` | Python库 | P1 | 10s |
| **AkShare东财快讯** | `ak.stock_info_global_em()` | Python库 | P1(备) | 10s |
| **同花顺7x24** | `https://news.10jqka.com.cn/tapp/news/push/stock/` | GET | P1 | 8s |
| **东方财富** | `https://np-listapi.eastmoney.com/comm/web/getNewsByColumns` | GET | P2 | 10s |
| **新浪财经** | `https://feed.mix.sina.com.cn/api/roll/get` | GET | P2 | 10s |
| **新浪7x24** | `https://zhibo.sina.com.cn/api/zhibo/feed` | GET | P2 | 8s |

### 3.2 投资日历数据接口

| 维度 | 接口/方式 | 说明 |
|------|----------|------|
| 新股 | `ak.stock_new_ipo_cninfo()` | 新股申购/上市/缴款日 |
| 解禁 | `ak.stock_restricted_release_queue_sina()` | 限售股解禁数量/占比 |
| 财报 | `ak.stock_yjbb_em(date=YYYYMMDD)` | 定期报告预约披露日 |

### 3.3 标准新闻数据结构

所有来源统一映射为以下格式：

```python
{
    'news_id':       'juchao_123456',     # 唯一ID（来源前缀+原始ID/哈希）
    'title':         '新闻标题',            # 标题
    'content':       '内容摘要',            # 内容摘要
    'publish_time':  '2026-09-07 10:30',   # 发布时间
    'source':        '巨潮资讯',            # 来源全称
    'source_tag':    '巨潮',                # 来源短标签（UI前缀【巨潮】）
    'news_type':     '公告',                # 公告/资讯/宏观/行业
    'category':      '公司公告',            # 业务分类（利好/利空/...）
    'stock_codes':   [{'code':'600519','name':'贵州茅台'}],  # 关联股票
    'hot_score':     85,                    # 热度值 0-100
    'url':           'http://...',          # 原文链接
    'is_new':        True,                  # 是否本次新增（UI高亮）
    'multi_source':  False,                 # 是否多源报道合并
    'extra_sources': ['新浪财经'],           # 多源报道的其他来源
}
```

### 3.4 核心API调用方式

```python
# 1. 获取多源新闻（并行拉取+异常降级）
from news_center import get_multi_source_manager
manager = get_multi_source_manager()
news_list = manager.fetch_all(limit=80)       # 返回标准格式新闻列表
status = manager.get_source_status()           # 获取各源状态

# 2. 智能去重
from news_center import get_deduplicator
dedup = get_deduplicator()
unique = dedup.deduplicate(new_news, existing_news=current_list)
dedup.mark_as_displayed(unique)                # 标记已展示（写入24h缓存）

# 3. 定时刷新引擎
from news_center import get_refresh_engine
engine = get_refresh_engine()
engine.on_refresh_success = my_callback        # 设置刷新成功回调
engine.start()                                  # 启动自动刷新
engine.set_active(True/False)                   # Tab切换时调整频率
engine.trigger_refresh(immediate=True)          # 手动触发

# 4. 投资日历
from news_center import get_calendar_provider
cal = get_calendar_provider()
events = cal.get_events('2026-09-07')          # 获取指定日期事件
range_events = cal.get_date_range_events('2026-09-07', '2026-09-14')
```

### 4.2 验收标准逐项验证

#### ✅ 验收1：自动刷新验证
1. 启动程序，切换到「实时新闻」Tab
2. 观察右上角「最后更新: HH:MM:SS」显示
3. 等待3分钟（或修改 `active_interval=60` 缩短为1分钟测试）
4. **预期**：无需手动点击刷新，内容自动更新，最后更新时间刷新，新增条目蓝色高亮8秒
5. 切换到「作战中控台」Tab，观察日志输出「降低刷新频率至600秒」
6. 切回「实时新闻」Tab，**预期**：立即触发一次增量刷新

#### ✅ 验收2：多源验证
1. 进入新闻页面，观察新闻列表
2. 检查新闻条目标题前的来源标签
3. **预期**：出现≥3种不同来源标注（【巨潮】【财联社】【同花顺】【东财】【新浪】等）
4. 来源下拉框应列出所有启用的数据源

#### ✅ 验收3：去重验证
1. 连续点击「刷新」按钮3次
2. 检查新闻列表标题
3. **预期**：无标题完全重复的新闻条目
4. 同一事件多源报道时，应合并为一条并标注「多源(来源名)」
5. 检查 `cache/news_center/display_cache.json` 文件存在且有内容

#### ✅ 验收4：投资日历验证
1. 进入新闻页面，点击「📅 投资日历」子Tab
2. **预期**：显示当日财经事件，按时间排序
3. 点击「后一天 ▶」/「◀ 前一天」切换日期
4. 使用类型下拉框筛选（新股/解禁/财报/宏观/事件）
5. **预期**：关联个股的事件显示「📊 股票名」按钮，点击跳转个股分析页

#### ✅ 验收5：稳定性验证
1. 程序连续运行30分钟
2. 交替切换各个Tab
3. **预期**：新闻模块无崩溃、无卡顿
4. 选股、行情等其他功能正常运行
5. 检查日志无未捕获异常

### 4.3 异常降级测试

1. **断网测试**：断开网络，点击刷新 → 应显示加载状态后恢复，不崩溃
2. **单源失败**：某个数据源接口超时 → 日志记录失败，其他源正常返回
3. **连续失败**：模拟单源连续失败3次 → 日志输出「临时降级停用」，下一轮自动恢复

## 五、异常兼容与安全保障

1. **模块导入降级**：`news_center` 导入失败时自动降级为旧版新闻逻辑，不影响程序启动
2. **网络异常捕获**：所有数据源请求包裹 `try/except`，单源失败不影响整体
3. **线程安全**：刷新引擎使用独立后台线程 + PyQt信号回到主线程更新UI
4. **内存控制**：最多保留500条新闻，24小时已展示缓存自动清理过期条目
5. **不影响其他模块**：新闻模块所有异常内部消化，选股、行情模块独立运行
